# 移动端菜单与静态素材缓存

## Context（上下文）

适用于赛事官网的移动端导航和公开静态资源加载。页面使用 `index.html` 的移动端媒体查询，导航是否展开由 `site.js` 修改 `.nav.open` 控制。

## Fact / Pitfall（事实或坑点）

- 仅存在 `.nav.open` 的 CSS 规则并不能打开菜单；必须在 `site.js` 中为 `.menu-toggle` 绑定点击事件。
- `showPage` 切页时需要同时移除 `.nav.open` 并重置 `aria-expanded`，否则切页后返回移动端会出现展开状态与实际状态不一致。
- 静态文件统一使用 `no-store` 会导致图片和音频每次访问都重新下载，移动端首屏和重复访问都会变慢。

## Solution / Convention（解决方案或规约）

- 移动端菜单使用 `toggleMobileMenu` 统一切换 CSS 类，并同步 `aria-expanded` 与 `aria-label`。
- 动态图片统一设置 `loading="lazy" decoding="async"`；首屏品牌图和主题标题图使用 `loading="eager"`。
- HTML、JavaScript、CSS 和 JSON 继续使用 `no-store`，保证部署后的代码与公开数据及时生效；图片、音频等媒体资源使用七天公共缓存。
- 首屏背景、主题标题和品牌图使用 WebP 版本，保留原始 PNG 作为素材源。
