# 赛事官网架构

## Context（上下文）

项目目标是为“蟑螂杯#3”提供公开赛事官网和单运营者后台。部署目标为 Ubuntu 24.04 + Docker，公开站点与后台共用一个无第三方依赖的 Node HTTP 服务。赛事状态由手工维护，页面需要在比赛尚未准备好时隐藏占位内容。

## Fact / Pitfall（事实或坑点）

- `data/competition.json` 是唯一赛事状态源，顶层固定为 `pages`、`event`、`rules`、`schedule`、`teams`。
- `pages` 的四个布尔值分别控制 `home`、`rules`、`schedule`、`ranking`。未发布页的公开接口返回 `content: null`，服务端不会把该页的占位数据发送给观众。
- `site.js` 只消费 `/api/public/:page` 的页面投影；`admin.js` 通过 `/api/admin/competition` 读取和保存完整状态。
- `scoring.js` 是前后端共用的计分规则模块。服务端为公开排名和积分数据生成 `computedScores`，前端不再自行重算权威分数。
- `/api/session` 建立内存会话；后台写接口和素材上传要求有效会话，并校验浏览器 `Origin`。凭据只能通过 `ADMIN_USERNAME` 与 `ADMIN_PASSWORD` 环境变量注入。
- 每次后台保存前，服务端在 `backups/` 生成 JSON 快照，然后用临时文件替换 `data/competition.json`。Docker Compose 必须挂载 `data`、`素材/上传` 和 `backups`。

## Solution / Convention（解决方案或规约）

```text
观众浏览器 /index.html + site.js
        │ GET /api/public/home|rules|schedule|ranking
        ▼
Node HTTP 服务 server.mjs ── scoring.js
        │                        │ 服务端权威计分
        │                        ▼
        ├── data/competition.json
        └── 素材/上传 + backups

运营者浏览器 /admin + admin.js
        │ GET/PUT /api/admin/competition
        │ PUT /api/assets
        │ POST/DELETE /api/session
        ▼
会话校验 → 数据校验 → JSON 快照 → 原子替换
```

- 后台分页：赛事信息、页面发布、规则文本、日程与选手、队伍与选手。
- 日程按 `playerIds` 引用选手；每个日期只绑定一个选手，初赛和决赛分开维护。
- 分队与结局图标由 `site.js` 中的正式名称映射到固定素材；抓位图由选手字段保存，可通过后台上传。
- 音乐加载后尝试自动播放；浏览器拒绝有声自动播放时，页面会在首次用户操作后重试，无法绕过浏览器策略。
- Docker 生产端口绑定到本机 `127.0.0.1:3101`，由已有域名和证书反向代理转发，避免直接暴露 Node 端口。

- 精英探索者由 `elite-explorers.js` 独立负责校验和公开投影，干员目录在 `six-star-operators.js`；一队一份整届指定，仅展示干员名称及可选头像；不登记选手逐局使用状态，不参与计分。具体契约见 `.context/conventions/精英探索者与网页图标.md`。
