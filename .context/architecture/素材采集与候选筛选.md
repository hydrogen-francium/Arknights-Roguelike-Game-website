# 素材采集与候选筛选

## Context（上下文）

运营者希望集中获取黑流树海和参考赛事的公开美术素材，再手动筛选；采集不是官网运行时功能，不允许自动应用下载内容。

## Fact / Pitfall（事实或坑点）

- 入口是 `npm run assets:collect`，工具为 `tools/asset-collector.mjs`，只使用 Node 内置模块。来源和限额在 `tools/asset-sources.json`，不读取后台凭据或赛事状态。
- 参考电脑页对应的手机页地址已从实际页面中核对。只提取配置页面及其直接引用样式的图片链接，不执行远程脚本、不全站递归。
- 页面脚本存在 `//[^` 一类正则表达式内容，不能用仅匹配双斜杠的词法把它当下载链接；链接提取必须具有完整域名。
- Wiki 的 `/w/文件:图片.png` 虽以图片扩展名结尾，响应仍是 HTML 文件说明页；采集时排除 `/w/` 文档地址，保留页面中的真实图床链接。相关回归测试不得只覆盖静态示例中的真实图片。
- PRTS 原图位于 `media.prts.wiki`；已核对的 `/thumb/散列/文件名/尺寸文件名` 转换为 `/散列/文件名`。参考图床的 `@` 后缀是图片处理指令，原图保留前半段。其他站点不推测转换规则。
- 默认候选目录位于仓库外：`../web-素材候选/`。项目静态服务能提供根目录下文件，候选内容不能放进项目根目录，否则会暴露未筛选资源。Dockerfile 的明确文件列表不包含采集工具。

## Solution / Convention（解决方案或规约）

- 白名单域名、单请求顺序、最低 1 秒间隔、图片数量和大小上限共同约束范围。禁止路径、网络错误或限额错误直接报错，不绕过限制、不自动重试。
- 每个来源检查 robots.txt；404 表示规则文件不存在，允许访问；其他非成功状态直接报错。重定向逐跳校验域名与抓取规则。
- 图片以 SHA-256 完整内容去重；清单保存原始图片地址及来源页面，原图独立存放。重跑校验已保存文件摘要，摘要不一致立即报错。失败也写出已完成部分的图库，不隐藏错误。
- `tools/asset-gallery/` 提供本地静态图库，清单内嵌并转义，图片懒加载。支持搜索、来源/分类筛选、背景切换、尺寸、勾选及导出清单。勾选不会跨刷新保留，刷新前必须导出。
- 不自动复制到官网 `素材/`，不把下载结果提交到 Git，不采集受登录保护的内容。人工筛选后再单独进行官网美术改造与压缩。公开下载不等于拥有使用授权。
