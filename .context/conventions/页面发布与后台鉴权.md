# 页面发布与后台鉴权

## Context（上下文）

运营者需要在赛事数据尚未确定时公开网站，但不能向观众暴露占位符、未安排好的赛程或半成品排名。因此每个公开页面都必须独立具备“已发布 / 页面筹备中”状态。

## Fact / Pitfall（事实或坑点）

- 只在前端隐藏内容是不安全的，浏览器仍可能收到完整 JSON；公开接口必须按页面投影数据。
- 后台编辑器需要完整赛事状态，但观众只需要当前页面的数据，因此两类接口不能共用返回结构。
- 服务器启动时不接受默认管理员密码；生产环境必须显式设置至少 16 位 `ADMIN_PASSWORD`。

## Solution / Convention（解决方案或规约）

- 页面开关存储在 `data/competition.json` 的 `pages` 对象中。
- 公开请求使用 `/api/public/:page`；关闭页面时返回 `pages` 和 `content: null`。
- 后台请求使用 `/api/admin/competition`；读取和保存都要求 `cc_session` 会话。
- 素材上传使用 `/api/assets`，只允许认证后台上传图片，服务端检查扩展名、文件大小和文件头。
- 登录会话当前存储在进程内存中，容器重启后失效；这是单运营者网站的当前边界，不应作为多用户权限系统使用。

- 部署变量示例：`.env.example`、`docker-compose.yml`、`README.md`。
